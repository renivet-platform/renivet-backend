# REN2-68 sustainability claims

`POST /api/v1/brands/{brandId}/products/{productId}/claims` accepts a normalized claim code/text, evidence asset IDs, optional claim expiry, an `If-Match` product row version, and an `Idempotency-Key`. The claim is bound server-side to the currently published product revision. Every evidence asset must belong to the same brand and be clean, derivative-ready, and rights-attested/reviewed. The mutation derives the actor from the W1 session, validates session-bound CSRF, rechecks `catalog.write` inside the transaction, and commits the pending claim, pending evidence, and immutable replay receipt atomically. It cannot verify or approve the claim.

`GET /api/v1/brands/{brandId}/products/{productId}/claims` returns claim history for the authorized brand-owned product. The list rechecks `catalog.read` and brand approval in the same SQL statement that returns rows. A stored `VERIFIED` state is exposed as verified only while the claim and every attached evidence record remain unexpired, accepted, unrecalled, and backed by a clean asset with valid rights. Expired or recalled evidence suppresses the live verified state while preserving the stored review record. Evidence IDs are returned for the owning brand; storage keys and signed/private URLs are never returned.

The additive `0019_ren2_68_sustainability_claim_lifecycle` migration adds row versions, recall metadata, indexes, immutable mutation receipts, and a guard requiring eligible media assets. `claim_review_events` is append-only. Independent moderator decisions remain in REN2-69; role grants remain owner-controlled. The disposable PostgreSQL 16 integration suite checks scope denial, atomic idempotency, expiry/revocation behavior, append-only history, and claim status suppression.
