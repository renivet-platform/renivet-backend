# REN2-64 price versioning

`PATCH /api/v1/brands/{brandId}/variants/{variantId}/prices` records an INR price proposal in paise. It requires the live brand-scoped W1 `pricing.write` permission, a session-bound CSRF token, an `Idempotency-Key`, and an `If-Match` variant row version. Price and MRP must be safe integer paise values, selling price cannot exceed MRP, and effective timestamps must include a timezone. Replays with the same key and request return the original receipt; changed payloads conflict.

`GET /api/v1/brands/{brandId}/variants/{variantId}/prices` lists price history only after a live, brand-scoped `pricing.read` permission check in the query. Both endpoints conceal variants outside the authorized brand. The W1 pricing permissions are defined by the migration but intentionally receive no role grants; requests remain denied until the owner-approved W1 role map grants them.

Migration `0015_ren2_64_price_versions.sql` adds audit attribution, compare-and-swap row versions, idempotency receipts, append-only price audit events, and lifecycle checks. PostgreSQL 16 retains the approved-window GiST exclusion from REN2-50 over `[valid_from, valid_to)`, treating a missing end as infinity. Pending proposals may overlap; concurrent approvals that overlap fail at the database constraint. Approved price rows remain immutable to ordinary updates and deletes.

REN2-65 implements `POST /api/v1/admin/brands/{brandId}/variant-prices/{priceId}/decision`. It requires the live brand-scoped `pricing.approve` permission, a fresh MFA step-up, session-bound CSRF, and an `Idempotency-Key`. The transaction rechecks permission, rejects creator self-review, compare-and-sets `PENDING` to `APPROVED` or `REJECTED`, and writes the before/after audit event plus immutable receipt atomically. A rejected price never enters the approved set. A conflict with an already approved effective window returns a conflict and leaves both the proposal and existing price unchanged. The migration defines `pricing.approve` without granting it to any role; W1 role authorization remains owner-controlled.

The disposable PostgreSQL 16 integration is `tests/w2/price.integration.test.cjs`; it covers persistence, tenant scoping, replay/conflict behavior, stale row versions, maker-checker enforcement, atomic approve/reject audit, concurrent approved-window exclusion, adjacency, and audit immutability. `proposeVariantPrice`, `listVariantPrices`, and `decideVariantPrice` remain subject to the W2 contract activation and permission approval gates; this PR is implementation evidence, not production activation authorization.
