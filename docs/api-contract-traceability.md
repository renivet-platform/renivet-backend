# W2 API contract and traceability

`openapi/renivet.openapi.json` and `src/generated/api-schema.d.ts` are executable artifacts. Generate them with `npm run api:generate`; the command exports the routes registered in the NestJS `AppModule` and derives the typed SDK from that export.

`openapi/W2_v1_5_CANDIDATE.yaml` is the approved v1.5 proposal from Engineering OS. Its 47 owner-approved operations remain design-only until a W2 implementation adds and registers real NestJS routes. Do not merge the candidate file into the executable OpenAPI or SDK to make those routes appear implemented.

`openapi/w2-operation-traceability.json` maps every candidate `operationId` to its v1.5 source IDs and a Linear owner issue from a dated Linear backlog snapshot that records each issue title and URL. The checker validates the snapshot and every owner link; it does not query Linear during CI, so Linear remains authoritative for live state. Design-only entries carry a pending test path and pending PR link. When a route is implemented, update the entry to `implemented`, set its test path to a verified test file, and add the open or merged PR URL. Local checks allow the PR field to remain pending before PR creation; CI requires the PR URL once the route is in executable OpenAPI. The checker requires the operation path, method, request DTO, response statuses and schemas, response headers, parameters (including idempotency and `If-Match`), named permission/guard/MFA metadata, W1 cookie authentication and session-bound CSRF policy to match the executable OpenAPI. It treats all `/api/v1/brands/*` and `/api/v1/admin/*` routes as W2 unless explicitly marked W1, and rejects undocumented live W2 routes and candidate operations exposed without matching test/PR traceability.

Run `npm run api:check` before opening or updating a PR. It builds the application, checks generated OpenAPI and SDK artifacts, checks Postman contracts, then validates W2 candidate count, source hash, owner/source mappings, design-only status, W1 cookie/CSRF/idempotency requirements and live-route traceability. The W2 contract tests also prove that status, error schema, DTO, ETag, idempotency and route-documentation drift fail the check.

The owner issue index is a snapshot from the W2 execution plan; its IDs were verified against Linear when this manifest was prepared. Linear remains authoritative for live issue state and dependencies.
